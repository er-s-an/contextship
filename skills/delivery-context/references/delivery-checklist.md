# Delivery checklist categories

Evaluate each category against tool output. Mark gaps only when evidence is missing or contradictory.

1. **Problem & acceptance** — description depth; measurable acceptance criteria / DoD.
2. **Ownership** — assignee present; reporter known.
3. **Dependencies** — “is blocked by” / “depends on” links still open; comment blockers.
4. **Implementation evidence** — linked PR(s) or explicit docs/process-only label.
5. **Review gate** — PR approval / open vs merged state.
6. **Verification** — test/QA signals in description, labels, comments, or PR checks.
7. **Release safety** — rollback, feature flag, or canary note for production-shaped work.
8. **Residual work** — open subtasks that would block “Done”.
